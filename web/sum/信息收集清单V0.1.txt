目标：
在不进行破坏性操作的前提下，建立目标的正常响应基线，
发现可能暴露内部实现、隐藏资源或后续分析入口的证据。

## 1. 正常页面与请求基线
[ ] 首页、登录页、商品/内容页分别访问一次
[ ] 记录请求方法、路径、关键参数、状态码、响应长度
[ ] 记录是否发生 302 跳转，以及跳转到哪里
[ ] 观察响应头：Server、Set-Cookie、Content-Type、Location

## 2. 页面源码与前端资源
[ ] 查看 HTML 源码中的注释、隐藏字段、data-* 属性
[ ] 查看加载的 JavaScript 文件
[ ] 关注接口路径、调试字段、版本号、环境标识、遗留链接

## 3. 常见公开索引文件
[ ] /robots.txt
[ ] /sitemap.xml
[ ] 发现路径后，分别确认：路径存在？可访问？需要权限？

## 4. 错误与异常响应
[ ] 使用“格式不符合预期”的普通输入，观察状态码和响应差异
[ ] 搜索 Exception、Error、Warning、Debug、Java、PHP、Python、admin、 等关键词
[ ] 记录：异常类型、框架/版本、内部路径、调用栈、数据库或接口线索
[ ] 不把“出现 404”直接认定为漏洞；先判断它是否只是正常业务响应

## 5. 备份、源码与配置线索
[ ] 关注 backup、old、test、dev、admin、config 等命名线索
[ ] 关注源码、备份、版本控制痕迹
[ ] 只记录已观察到的证据，不把猜测写成事实

## 6. 证据记录格式
[ ] 正常响应是什么？
[ ] 异常响应是什么？
[ ] 两者差异是什么？
[ ] 这些差异能支持什么假设？
[ ] 下一步如何在授权环境中验证？
